# 多分类对齐、CLI 重构、HTTP 服务与多模态决策落地

完成了多分类与分级打分能力设计、命令行参数体系正交化重构、常驻 HTTP API 服务开发、Gemma 4 原生多模态视觉决策支持以及 JevBench 231 题基准评测。

## 1. 互斥多分类 (choose) 与分级打分 (score) 机制

在二元判定之外，决策任务常涉及单选分类与程度分级。系统引入基于 Token 掩码的单步前向算法。

### 多分类选择与位置对冲

对 $K$ 个候选类别，Prompt 给出选项列表并引导模型输出对应选项编号（如 A、B、C 等）。

提取各选项 Token 的原始 Logits $\{l_1, l_2, \dots, l_K\}$，通过 Softmax 计算归一化概率分布：
$$P_k = \frac{e^{l_k / \tau}}{\sum_{j=1}^K e^{l_j / \tau}}$$

由于大模型评估时常存在选项首尾位置偏好，系统提供 `--debias-order` 参数。开启后执行正序排列与逆序排列两次前向计算，将各类别未归一化 Logits 取算术均值后再做 Softmax：
$$l_k^{\text{debiased}} = \frac{l_k^{\text{forward}} + l_k^{\text{reverse}}}{2}$$

### 分级量规连续打分

输入 `--levels` 刻度标签（如「低, 中, 高」或 5 档满意度），模型输出对应等级离散概率分布 $\{P_0, P_1, \dots, P_{M-1}\}$。连续期望得分为各等级索引的概率加权和：
$$E = \sum_{i=0}^{M-1} i \cdot P_i, \quad E_{\text{norm}} = \frac{E}{M - 1}$$

## 2. CLI 参数体系重构与生命周期服务

为了使命令职责明确，将原先混杂的参数体系按输入形态正交拆分：
- 单条子命令（`noun`, `choose`, `score`）：仅接收命令行字符串（`--rubrics`, `--context`），不接收文件。
- 批量子命令（`batch noun`, `batch choose`, `batch score`）：仅接收数据文件（`--input data.json`），支持流式处理、`--filter-passed` 过滤与 `--include-record` 附带原始字段。
- 彻底移除单字母短参数（除 `-h` 帮助外），统一使用长参数显式命名。

增加常驻服务与进程管理命令：
- `decision-cli serve`：基于 Go 标准库暴露 HTTP API，提供 `/health`、`/v1/noun`、`/v1/choose`、`/v1/score` 以及兼容 TypeSafe Jev 的 `/v1/systemone` 复合多问端点。
- `decision-cli kill`：扫描并终止系统残留的 MLX Worker 守护进程，释放统一内存并清理 `.sock` 文件，支持 `--dry-run` 预览。

## 3. Gemma 4 原生多模态视觉决策

系统扩展了基于 Gemma 4 视觉编码器的图文多模态判定能力。

### 视觉前向机制
- 利用模型内置的视觉投影模块，将单张或多张输入图片编码为固定长度的视觉 Token 序列。
- 纯文本模型（如 Qwen3-Reranker）在传入 `--image` 时直接报错拦截。
- 支持单图二元判定（如检测截图中是否包含报错弹窗）与多图对比选择。在双图对比中，Prompt 通过占位符引用图片序列：
  `第一张图：{{image:1}} 第二张图：{{image:2}}`
- 多图场景同样支持 `--debias-order`，消除图片排列先后的位置偏置。

## 4. JevBench 公开 231 题基准评测

使用 HuggingFace 公开的 Praveenrajus/jev-bench 评测集（231 条样本，覆盖 7 类真实场景，分为 Easy、Standard、Hard 三种难度），评测各模型在单步 Logits Prefill 模式下的准确率：

| 模型名称 | 激活参数量 | Easy (48题) | Standard (72题) | Hard (111题) | 综合准确率 (231题) | 单条前向耗时 |
| :--- | :--- | :---: | :---: | :---: | :---: | :---: |
| qwen3-reranker-4b | 4B | 97.9% | 69.4% | 18.2% | 50.6% | ~52 ms |
| gemma-4-e4b | 4.5B | 97.9% | 97.2% | 42.1% | 71.0% | ~65 ms |
| gemma-4-26b-a4b | 3.8B (总26B MoE) | 100.0% | 100.0% | 68.5% | 84.8% | ~170 ms |

根据测试结果，将系统默认推荐模型从 qwen3-reranker-4b 切换为综合表现更均衡的 gemma-4-26b-a4b。

## 5. 网页划选油猴脚本

为了方便在浏览器中快速调用本地模型进行内容审查与辅助标注，编写了 Tampermonkey 用户脚本。用户在网页中划选文本或区域截图后，脚本向本地常驻 HTTP 服务（默认端口 8998）发送请求，浮层展示判定结果与置信度。
