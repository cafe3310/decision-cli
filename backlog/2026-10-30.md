# 适配 Ling-3.0-tiny、状态栏监控与开源发布自检

在此阶段完成了端侧轻量模型 Ling-3.0-tiny 的接入适配、macOS 原生状态栏监控开发、全局单例 Worker 显存保护、四模型硬件与基准评测、原生卸载命令实现以及开源发布前自检加固。

## 1. 适配 Ling-3.0-tiny 端侧轻量模型

为了满足高吞吐场景下的低延迟需求，系统接入了基于混合线性注意力架构的 Ling-3.0-tiny (4-bit MLX)：
- 架构特性：采用混合线性注意力（Hybrid Linear Attention）与 MoE 结构，总参数 7.9B，单次前向仅激活 1.3B 参数。
- 性能表现：单条前向耗时约为 45ms，在 JevBench 231 题基准集上取得 69.7% 的综合准确率。
- 适用场景：适用于高频次、对响应时间要求严格的纯文本二元过滤与意图判定。

Prompt 格式采用 Ling 默认对话模板，在序列末尾提取「是」与「否」的原始 Logits，经温度校准后输出概率。

## 2. macOS 原生状态栏图标与实时状态展示

为了让本地常驻推理进程的运行状态直观可见，开发了纯 Go 实现的 macOS 原生系统菜单栏常驻程序（`decision-cli statusbar`）：
- 状态监视：实时轮询常驻 MLX Worker 的进程存活状态、当前加载的模型名称以及物理统一内存占用。
- 快捷操作：菜单项提供一键重启 Worker、扫描清理进程、查看日志以及退出功能。
- 无第三方运行时依赖：基于系统原生 Cocoa/AppKit API 绑定实现，直接编译进单一 Go 二进制程序中。

## 3. 全局单例 Worker 与显存保护机制

针对连续或并发调用 CLI 时可能误启动多个 Python 进程导致显存占满的问题，增加了单例守护机制：
- 文件锁协同：通过 `~/.cache/decision-cli/worker.lock` 进行互斥排他控制。
- 懒探活：Go CLI 在发起推理请求前，先向 Unix Domain Socket 发送轻量 Ping 探针。确认服务存活后直接复用连接，避免重复拉起 Worker。
- 统一退出清理：执行 `kill` 或 `uninstall` 时，按系统进程表精准定位所有属于 decision-cli 的 Python 进程并清理残留的 `.sock` 文件。

## 5. 原生卸载命令与无依赖回退

为了保证工具对本地系统的环境整洁度，实现了 `decision-cli uninstall` 子命令：
- 进程与缓存清理：扫描并终止系统中的 MLX Worker 守护进程与状态栏进程，移除 `~/.cache/decision-cli` 下的虚拟环境与 SQLite 缓存库。
- 完整清除支持：提供 `--yes`（跳过交互确认）与 `--all` 参数，可一并移除 `~/.config/decision-cli` 全局配置目录。
- 编译产物指引：在文档中给出使用 `trash` 移至废纸篓的指引。

强化了运行时的零外部工具链依赖支持：当宿主机未安装 `uv` 时，自动回退使用 Python 3.10+ 标准库 `venv` 创建自包含环境，并在环境中预装 `huggingface_hub[cli]`，确保模型下载与环境准备均能自动化执行。

## 8. 末层候选 Token 切片投影优化 (`--sliced-head`)

参考 `jevos` 中仅提取末位隐藏状态并按候选词切片投影的思路，在 `internal/infra/mlx_worker.py` 中实现了末层输出头切片优化，并设为全模型默认开启（支持 `--sliced-head on|off` 与 `DECISION_SLICED_HEAD=on|off` 切换）：
- 计算路径：仅取 Transformer 主干最后一位隐藏状态 `h[:, -1:, :]`，并按候选 Token ID 对输出层权重（兼容 `QuantizedEmbedding`、`QuantizedLinear` 与 `Linear`）按行切片后执行局部矩阵乘法，省去前 $T-1$ 个位置的全词表投影与全词表 `logsumexp` 规约。
- 数值等价性：二元 Margin 与多选/打分局部 Softmax 中的全词表归一化常数精确相消，决策结果与 Margin 保持一致。
- 稳态实测收益：
  - 短至中等上下文（32 ~ 1200 tokens）：`ling-3.0-tiny` 提速 6.2% ~ 10.5%，`qwen3-reranker-4b` 提速 14.3%，`gemma-4-e4b` 提速 9.9% ~ 14.5%，`gemma-4-26b-a4b` 提速 4.1%。
  - 多模态图文判定（280 Soft Tokens）：`gemma-4-e4b` 与 `gemma-4-26b-a4b` 分别节省 19.0 ms（+9.1%）与 29.1 ms（+11.8%）。
  - 长上下文场景（3.5k ~ 6k tokens）：各模型单次前向节省 86 ms ~ 759 ms（提速 8.6% ~ 12.0%）。
